System-Diagramm

Schlüsselentscheidungen in dieser Schicht

  • Speisekarte als JSON im Repo — bei Build geladen, in Edge-CDN gecacht. Keine DB-Query, keine Latenz, offline verfügbar via Service Worker.
  • Bestellungen via Server-Functions — Idempotenz-Key gegen Doppel-Klicks; Webhook-driven (Stripe/PayPal callen zurück, nicht Client).
  • Bondrucker via CloudPRNT-Polling — Drucker fragt alle 3–5s den Server „neuer Auftrag?". Kein Port-Forwarding, kein VPN nötig. Funktioniert im normalen Restaurant-WLAN.
  • EU-Hosting — Vercel Frankfurt-Region + Supabase Frankfurt + Resend EU. DSGVO-Datenresidenz minimal halten.
  • PWA-Layer — Service Worker macht die Seite installierbar (Add to Home Screen), Speisekarte offline lesbar.
