Bestellfluss — was passiert wann

End-to-End Sequenz

Wichtige Fluss-Details

  • Preise immer server-seitig neu rechnen aus menu.json + zones.json. Niemals Client-Preisen vertrauen — sonst kann jemand 0,01 € pro Pizza an den Server schicken.
  • Idempotenz-Key beim POST /api/orders: gleicher Key → gleiche Order zurück. Schützt vor Doppel-Klicks und Netzwerk-Retries.
  • Webhook ist die Wahrheit, nicht der Browser. Der Server vertraut dem Stripe/PayPal-Webhook (signiert) — wenn Browser ohne Webhook-Bestätigung „bestätigt", bleibt die Order auf pending_payment.
  • Bondrucker-Polling via CloudPRNT: Star/Epson-Drucker fragen alle 3–5s den Server „neuer Auftrag?". Du brauchst nur einen WLAN-fähigen Drucker (z. B. Star mC-Print3 ~250 €) — kein VPN, kein Port-Forwarding.
  • Drucker-Ausfall-Strategie: Wenn 2 Min keine Bestätigung vom Drucker → E-Mail/SMS-Backup an Restaurant + Hinweis im Admin-Panel. Order geht nie verloren.
  • Snapshot der Items im order_items — wenn sich Speisekarte ändert, bleibt die alte Bestellung korrekt lesbar (Buchhaltung, Reklamationen).
  • Status-Polling für Kunde: /bestellung/[short_code] pollt alle 15s den aktuellen Status („vorbereitet → Fahrer unterwegs → geliefert"). Restaurant setzt Status im Admin-Panel.
