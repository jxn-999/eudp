PWA & Performance

App-Feel via PWA
  • Web-App-Manifest + Service Worker (next-pwa) — installierbar als Icon
  • Splash-Screen mit Logo, eigenes App-Icon
  • Vollbild-Modus ohne Browser-Chrome nach Install
  • Speisekarte offline-lesbar (cached menu.json + Bilder via SW)
  • Cart bleibt offline — Zahlung braucht aber Online
  • Install-Prompt erscheint nach 2. Besuch (nicht nervig)
Performance-Targets
  • Lighthouse-Score ≥ 90 auf allen 4 Achsen
  • LCP < 2,5 s, INP < 200 ms, CLS < 0,1
  • Bilder via next/image — automatisches AVIF/WebP, lazy load, srcset
  • Bildoriginale werden bei Build optimiert (Build-Step)
  • Speisekarten-JSON als statische Asset im CDN, vor-rendered
  • Schriften: next/font mit subsetting (nur DE-Zeichen)
  • Bundle-Size: pro Seite < 100 kB JS (gzip)

Compliance — was rechtlich Pflicht ist

DSGVO / TDDDG (Telekommunikation-Digitale-Dienste-Datenschutz-Gesetz)
  • Cookie-Banner mit echter Wahl (Ablehnen mind. so prominent wie Annehmen). Nur essentielle Cookies vor Einwilligung.
  • Datenschutzerklärung auf /datenschutz — listet alle Verarbeitungen: PayPal, Stripe, Vercel, Supabase, Resend, OpenStreetMap. Mit Auftragsverarbeitungsvertrag (AVV) bei jedem Anbieter.
  • OpenStreetMap statt Google Maps — datenschutzfreundlicher, keine Cookies, in DE rechtssicher.
  • Speicherdauer der Bestelldaten: 10 Jahre (HGB §257) für Kassenbelege, danach Löschung. Im Datenmodell anonymisierbar machen (Gast-Daten getrennt von Bestelldaten via FK).
  • Right-to-be-forgotten: Endpunkt im Admin, der personenbezogene Daten anonymisiert (Bestelldaten bleiben für Buchhaltung, aber ohne Name/Adresse).
  • EU-Hosting: Vercel Frankfurt, Supabase Frankfurt, Resend EU. Kein US-Anbieter im kritischen Pfad. (Stripe + PayPal sind US, aber rechtskonform per Standardvertragsklauseln + DPA.)
LMIV (Lebensmittelinformations-Verordnung EU 1169/2011)
  • Bei vorverpackten Lebensmitteln im Online-Verkauf: Allergene + Zutaten + Nährwerte vor Kauf-Bestätigung sichtbar.
  • Bei fertig zubereiteten, nicht-vorverpackten Speisen (Pizza, Döner) gilt der weniger strenge §44 LMIDV: 14 Pflichtallergene + Zusatzstoffe pro Item müssen angegeben werden.
  • Praktisch: Pro Item-Modal-Box „⚠ Allergene: Gluten, Milch · Zusatzstoffe: 1 (Konservierungsstoff)".
  • Sammel-Liste der Allergene + Zusatzstoffe-Code-Tabelle auf /speisekarte#allergene oder eigene /allergene-Seite.
Pflichtseiten
  • /impressum — TMG §5: vollständige Anschrift, vertretungsberechtigte Person, Telefon, E-Mail, USt-IdNr., zuständige Behörde, OS-Plattform-Link (EU)
  • /datenschutz — DSGVO Art. 13 (siehe oben)
  • /agb — Allgemeine Geschäftsbedingungen, Bestellprozess, Lieferung
  • /widerrufsrecht — Achtung: frisch zubereitete Speisen sind vom Widerruf ausgeschlossen (§312g Abs. 2 Nr. 4 BGB) — das muss klar im Checkout erscheinen
  • Verbraucherinformationen pre-Checkout: Lieferzeit, Versandkosten, Zahlungsmethoden, Gesamtpreis vor dem „Kostenpflichtig bestellen"-Button (§312j BGB — Button-Lösung)

MVP-Roadmap — Phasen

Phase 1 — MVP (1–2 Wochen)
Fokus: Online sein, lesbar, kontaktierbar.
✓ Next.js-Setup + Tailwind + i18n-Grundgerüst
✓ Statische Webseite: Startseite + /speisekarte (Lese-Version) + Über-uns + Standort + Kontakt + Impressum + Datenschutz
✓ menu.json mit allen ~200 Items, vorerst ohne Bilder (Platzhalter pro Kategorie)
✓ OpenStreetMap-Einbettung, Footer, Side-Drawer-Nav
✓ Deploy auf Vercel mit Custom-Domain
Ziel: Restaurant ist gefunden, Speisekarte lesbar, Kontakt klar.
Phase 2 — Bilder + Shop-Skelett (2–3 Wochen)
✓ Bilder-Pipeline: Foto-Shoot organisieren oder per AI generieren, ins Repo, next/image
✓ /shop-Bereich mit Item-Grid, Item-Modal, Cart (lokal)
✓ 3-Schritt-Checkout-Skelett ohne Zahlung („Bestellen via Anruf")
✓ PWA-Manifest + Service Worker
Ziel: Shop sieht fertig aus, sammelt Bestellungen via Telefon-Notiz.
Phase 3 — Echte Zahlung + Backend (2 Wochen)
✓ Supabase-DB + orders/order_items/print_jobs
✓ Stripe-Integration (Karten + Apple/Google Pay)
✓ PayPal-Integration
✓ Bestellbestätigung per E-Mail (Resend)
✓ Bestätigungsseite mit Status-Stepper
✓ Cookie-Banner, vollständige Rechts-Seiten
Ziel: Bezahlte Online-Bestellungen funktionieren ende-zu-ende, Restaurant kriegt E-Mails.
Phase 4 — Bondrucker + Admin-Panel (1–2 Wochen)
✓ Star/Epson WLAN-Bondrucker einrichten
✓ CloudPRNT-Endpoint im Server (Drucker-Polling)
✓ ESC/POS-Bon-Vorlage (Header, Items, Summe, Code, QR)
✓ Admin-Panel mit Login: Order-Liste, Status setzen, Drucker-Status
✓ Drucker-Ausfall-Backup (E-Mail/SMS)
Ziel: Restaurant-Workflow ohne manuelle Schritte. Bestellung → Bon → fertig.
Phase 5 — Optional / Später
Englische Übersetzung · Galerie-Seite · Pizza-Hour-Banner zeitgesteuert · Tisch-Reservierung · Bewertungen / Google-Reviews-Snippet · A/B-Tests für CTAs · Newsletter
