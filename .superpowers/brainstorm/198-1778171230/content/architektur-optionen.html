Drei Architektur-Ansätze im Vergleich

Basierend auf deinen Antworten — Empfehlung markiert. Klick auf eine Karte zum Auswählen, oder antworte im Terminal.

Vorab — zur DB-Frage: Komplett ohne Datenbank geht nicht. Bestellungen müssen persistent gespeichert werden (sonst sind sie weg, wenn der Server neustartet). ABER: Du brauchst keine „große" DB. SQLite oder Supabase-Free-Tier reicht für 1000+ Bestellungen/Monat. Die Speisekarte (200 Items) liegt als JSON im Code — keine DB dafür nötig.
★ Empfohlen
Option A: Next.js + Serverless
Browser → Next.js App (Vercel)
↓ Speisekarte als JSON
↓ Bestellung →
Serverless Functions
↓ DB: Supabase (Postgres)
↓ Stripe / PayPal
↓ Bondrucker (CloudPRNT)
↓ E-Mail (Resend)

Was steckt drin

  • Frontend: Next.js App Router + TypeScript + Tailwind
  • Speisekarte: JSON-Datei im Repo (build-time geladen)
  • i18n: next-intl (DE/EN)
  • Bilder: next/image — auto AVIF/WebP, lazy load
  • Orders: Supabase (Postgres, Free-Tier 500 MB)
  • Payment: Stripe Elements + PayPal SDK
  • Hosting: Vercel Free-Tier, custom Domain

Pro

  • Modern, performant (Lighthouse 95+)
  • Bilder-Optimierung „für lau"
  • Free-Tier reicht für deine Größe
  • Sehr gute Doku, viele AI-Beispiele
  • Skaliert ohne Migration

Contra

  • Setup-Aufwand höher als Static
  • Eine kleine DB nötig
  • Vercel/Supabase als Vendor
Static-first
Option B: Astro + minimal Backend
Browser → Static HTML (Astro)
↓ Bestellung →
Cloudflare Worker
↓ DB: Cloudflare D1 (SQLite)
↓ Stripe / PayPal
↓ Bondrucker / E-Mail

Was steckt drin

  • Frontend: Astro (HTML-first, JS nur wo nötig)
  • Speisekarte: Markdown/JSON, build-time generiert
  • Orders: Cloudflare Worker + D1 (SQLite, kostenlos)
  • Hosting: Cloudflare Pages (komplett kostenlos)

Pro

  • Maximal performant (statisches HTML)
  • Kostet 0 € auf Cloudflare
  • Weniger JS-Komplexität

Contra

  • Bilder-Pipeline manuell aufbauen
  • Cart/Checkout = Eigenbau (mehr Code)
  • Cloudflare Workers = JS, andere DX
  • Weniger AI-Trainingsdaten
No-Code-Pfad
Option C: WordPress + WooCommerce
Browser → WordPress (PHP)
↓ MySQL (alles drin)
↓ WooCommerce + Plugins
↓ z.B. „Restaurantpress"

Was steckt drin

  • CMS: WordPress (Admin-Panel)
  • Shop: WooCommerce + Restaurant-Plugin
  • Hosting: Hetzner/All-Inkl (~5–10 €/Mon.)

Pro

  • Inhaber kann selbst Inhalte ändern
  • Fertige Plugins für vieles
  • Viele Agenturen kennen es

Contra

  • Performance schwächer (Lighthouse ~60)
  • Plugin-Hell + Sicherheits-Updates
  • 200 Items langsam
  • DSGVO mit WP/Plugins ein Minenfeld
  • Lock-in, schwer zu erweitern

Meine Empfehlung: Option A (Next.js)

Warum: Du sagtest „benutzerfreundlich + performant" + „ich baue es selbst mit AI-Hilfe". Next.js ist genau dafür optimiert: built-in Bilder-Pipeline (kritisch bei 200 Items mit Fotos), sehr viel AI-Trainingsmaterial, free-tier ausreichend, ein einziges Mental-Model (React/JS überall). Eine kleine Postgres-DB für Bestellungen ist nicht „eine große Datenbank" — es ist 5 Tabellen und ein Free-Tier-Account.
